### Phase 9 — branch statement projection from attested canonical lines (Draft only)

- Added `lib/financial-branch-statements.ts`: a read-only, exact-four-decimal, per-headquarters / per-branch financial statement compiler over a complete canonical company `StatementSource` and a one-to-one opening/journal-line attribution manifest. Uses the existing independent opening/movement balance validator; rejects missing, duplicated, altered, stale or unknown allocations. Each segment's journals are compiled through the existing accounting engine, not by subtracting display totals.
- Every income, financial position and cash-flow control metric from the segments must reconcile exactly to the entire legal company. Any failed check suppresses ALL segment figures. Reversal lineage is never fabricated; incorrectly split reversals fail the segment compiler.
- This is a **preview-only computational capability**. It does **not** claim that a trusted server extraction/approved opening allocation table exists, or that branch/cost-center controls may be enabled on production. Next gate: versioned server-authoritative opening and journal attribution with full RLS/authentication and audit, plus isolated end-to-end testing with real representative branch and transfer fixtures. Group consolidation still needs separate control, eliminations, FX and NCI work.

### Phase 10 — authorized canonical journal → company/branch reference bridge

- Added `services/financial-branch-journal-source.ts`, an authenticated server-only read-side adapter for Financial Core's posted event references. It matches **every** requested canonical journal ID/date/status to RLS-visible events; verifies active `COMPANY`/`BRANCH` registry membership, treats null entity as legitimate headquarters, and re-checks active membership plus `financial_core.view` after reading. Stale/duplicate/hidden/unknown/legacy identifiers fail closed without partial figures or database error disclosure.
- Added `tests/financial-branch-journal-source.test.ts` covering direct HQ, company-linked activity, branches, source mismatch, revocation, RLS omissions and errors.
- **Scope limitation:** observation `RLS_MATCHED_JOURNAL_REFERENCES_ONLY` is not authoritative revision attestation and does not supply approved branch opening allocations; it cannot enable branch-level statutory financial statements or their exports. It is the read-side prerequisite for the still-pending audited versioned allocation mechanism. No schema, data or Production changes.
