## ملكية المصادر

| النوع أو الحركة | مصدر الحقيقة | دلالة كشف الأصل |
|---|---|---|
| افتتاح شخصي أو مؤسسي مسجل وشراء وإضافة | `transactions` + `lots.source_transaction_id` | كمية وتكلفة الدفعات الأصلية من الدفعات. مبلغ السند والعملة من المعاملة. اعتراف الشراء المؤسسي من `financial_events` ووسم `recognition_pending`. افتح قيد FC V2 من مصدره إن توفر. |
| ذهب وفضة ومخزون شخصي | `lots` + `transaction_allocations` | بيع أو سحب جزئي يخصم الكمية وتكلفة FIFO المسجلة. سعر البيع والقبض مستقلان عن التكلفة. يظل وزن/وحدة كل أصل كما سُجلت. |
| عقار وسيارة ومقتنيات شخصية | فتح/شراء/بيع في سجل الدفعات، وقيمة حالية وصفية في `asset_accounts.metadata` | لا نفترض تاريخ تقييم أو إهلاك شخصي. الإيجار والصيانة والدين في مصادرها المتخصصة عند توفر الربط. |
| معدات وأثاث وأصول ثابتة مؤسسية | `asset_lifecycle_commands` + `financial_events` + `transactions` | صف العملية المطبقة من المعاملة، وتغير الدفعات من `lot_states` عند توفرها. عند الإهلاك لا تنقص الكمية. أمر مسودة غير مرحل يظهر دون أثر على الرصيد. |
| استبعاد شخصي | تخصيصات الدفعات أو أثر التكلفة المسجل في المعاملة | المتحصلات والتكلفة مختلفتان. صفر متحصلات عند الاستبعاد الموثق بدون مقابل. |
| عكس / تصحيح | `reversal_of_transaction_id` وروابط #461؛ سجل `financial_event_status_history` للمؤسسي؛ `audit_logs` ومراجعة السعر لـ #472 | عكس صريح إلى تاريخ أثره. تعديل السعر يعرض القيمة الحالية للسند وسجل التصحيح دون إعادة تخصيص. كشف تاريخ الحركة يعرض السندات وفق التاريخ الفعلي وقيمها المصححة الحالية. |
| الذمم والسيولة المؤسسية | `financial_event_obligation_balances` و`financial_events`؛ `liquidity_accounts` | السجل يعرض إسقاطًا بأرقام `receivable:` و`cash:`. لا يعاملها كشف الدفعات كأصول مستقلة. |
| النقد الشخصي والاستثمارات والتمويل والذمم | الدفعات النقدية للعمليات المحلية؛ الوحدات الأصلية للسيولة والاستثمارات والذمم والتمويل | تبقى الوثائق الأصلية في مصدرها. روابط الدفعات للعمليات المحلية تعرض الأثر مرة واحدة. |
| زكاة وحول | `zakat_assessments` + `zakat_assessment_lines` + `zakat_payment_allocations` | معلومات الزكاة حُسبت في مصدرها. لا تُستنتج من كشف الحركة ولا يعاد بناء اللقطة. |
| السوق وFX | سعر السوق المدخل مع عملته وتاريخه، وسعر التحويل المخزن لكل معاملة | عمود قيمة العملية يحتفظ بعملته. لا يجمع الكشف تكاليف أساس مختلفة ولا يسند قيمة سوقية من التكلفة. |

## UX-01 وA1

| النطاق | الفجوة | انتقال المرحلة |
|---|---|---|
| UX-01-01 | التفاصيل الحالية موجزة والنوافذ الحالية لا توحّد الملخص والكشف والإجراء | UX-01b لتبويبات الكشف ثم UX-01c للنماذج داخل البطاقة |
| UX-01-02 | لا API قراءة موحد لأصل واحد ولا دليل مطابقة تاريخية لكل نوع | UX-01a للقراءة، وتاريخ مرجعي وتسلسل ثابت وفصل المبالغ عن التكلفة |
| UX-01-03 | حقول نوع الأصل ومجمع الإهلاك وتاريخ السوق ليست متاحة لجميع الصفوف | UX-01b يعرض فقط ما يثبته المصدر؛ A2/A3 للحقول المتقدمة |
| UX-01-04 | زر الدورة ينقل إلى العمليات أو يستبدل نافذة التفاصيل بنافذة مستقلة | UX-01c يعيد استعمال `AssetLifecyclePanel` وواجهات الحفظ بعد A1 |
| UX-01-05 | CI لمساري تصحيح البيع موجود؛ يلزم إثبات كشف الأصل، السيناريو المؤسسي والتصدير وعزل النطاق | اختبارات رقمية وواجهة على بيانات معزولة، ثم تنسيق #426 |

عقد A1 المقترح يعرّف `effective date` و`recorded at` وعملة العملية وعملة أساس التكلفة، ويفصل الكمية ومبلغ السند وأثر التكلفة والقيمة السوقية. التاريخ في UX-01a هو تاريخ أثر الحركة وفق السجل الحالي، مع التصحيحات المسجلة لاحقًا. عند نقص القيد أو اختلاط أساس التكلفة يعود الرصيد غير مؤكد بدل التخمين. مصدر الدفعات الحالي وسجل الأستاذ قد يتطلبان تسوية مستقلة للقيود القديمة. الترقيات الكتابية وتعبئة البيانات القديمة تحتاج اختبار توافق وخطة تراجع في A1/A2. UX-01a إضافة للقراءة يمكن التراجع عنها بإزالة الواجهة والخدمة دون ترحيل أو كتابة.
