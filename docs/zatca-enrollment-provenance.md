## Persistence flow

1. `begin_initial_enrollment` locks active OWNER/ADMIN membership, then the saved connection. A new request requires KEY_READY, a saved key reference, no credentials and no signer registry version. It captures the exact original public CSR DER, public SPKI, requester email, expected identity derived from the saved connection, actor/time, unit stamp and enrollment digest. Unit stamp includes original key/identity, excluding the secret reference that does not exist yet. One initial request per company/environment/connection; exact retries preserve the original record even after credentials appear. Changed operation/CSR/key/identity/email is rejected. It does not support starting a fresh enrollment for a changed unit/key as an automatic renewal/recovery shortcut.
2. A future authorized backend must load that **saved** request/identity, verify current KMS metadata, call `verifyZatcaOnboardingCandidate` with independently configured roots/fresh CRLs, capture the actual immutable AWS VersionId/certificate/policy material and update saved connection references consistently. No current route performs this flow yet.
3. `record_enrolled_signer_candidate` locks membership/connection, rechecks the original unit stamp, binding scope/references and complete verification receipt, then records the private signer version and immutable enrollment link/check atomically. Evidence must have the exact candidate/identity/path shape, matching CSR/SPKI/certificate/chain/anchor and environment, unique bounded CRL fingerprints, OpenSSL 3 metadata and a check time within five minutes (at most five seconds ahead of DB time). New checks append history while the first check/link remain unchanged; exact evidence retries deduplicate. An existing legacy registry version cannot receive original provenance retroactively.
4. An AFTER INSERT trigger on the original signer reservation captures its enrollment digest/first-check reference in the same transaction, only when its registry version already has enrollment provenance. No UPDATE or backfill path exists. `reserve_with_enrollment` requires that captured reference and exact expected original digest; failure rolls back the attempted reservation and source freeze.
5. `finalize_with_enrollment` reuses current authorization, saved source/config/registry checks and the existing atomic signer finalizer, then records one immutable enrollment audit with the artifact/head/other audits. Exact retries preserve the first values. Missing original enrollment audit cannot be attributed after legacy preparation, and conflicting audit rolls back the whole finalization.

No procedure issues a document, makes an authority request or creates financial/cash projections. Prepared sources remain DRAFT/frozen. Generic ledger/source/signer helpers remain private test primitives; a future production coordinator must use the enrollment-aware path consistently and must not fall back to a weaker helper after rejection.

## Complete saved identity receipt

The Node identity result now includes `expectedIdentitySha256`. Its versioned byte framing, `ZAKATFLOW_FLAT_IDENTITY_V1`, sorts the flat identity's ASCII keys and concatenates each UTF-8 key and value, each prefixed by its four-byte unsigned big-endian byte length. PostgreSQL reproduces it with C ordering, UTF-8 conversion and `int4send`; it does not hash JSON display whitespace or JavaScript character counts. Arabic parity is checked in the native SQL integration.

The SQL writer compares this receipt with the **original stored identity**, not just CSR/key hashes. This blocks replay of evidence generated against a different expected snapshot: notably the current simulation CSR writer has a constant CN, so a changed saved commonName need not change that CSR. The native integration deliberately computes such a different-snapshot result and confirms SQL rejects it before recording a version.

## Limits of the boundary

SQL checks storage, authorization and consistency, **not PKIX, CSR signatures, revocation, AWS ownership or authority approval**. The native verifier's stage/shape is not a cryptographically signed assertion; its caller is a trusted private backend. CSR/SPKI parameters are intended public material and bounded canonical base64, but SQL is not a DER signature parser. Never expose these functions to application roles or accept a client-supplied proof as verification. The backend must run native verification, validate the original CSR/public SPKI and return only sanitized errors, not native SQL diagnostics.

The five-minute timestamp rule is a persistence freshness bound, not proof that a CRL is the newest remote publication. Saved evidence is an immutable historical audit, not an evergreen signing authorization. Fresh configured trust/CRLs, current permissions and registry state still need rechecking at actual signing/finalization. Production enrollment, original-request submission/retry state, current authority identity/CP/CPS mapping, same-key renewal policy and changed-key/unit recovery remain to be reviewed. No persistent registry V2/migration, cloud credential or live writer is supplied by this fixture. An isolated authenticated initial-request preservation adapter is now implemented separately; it does not submit to the authority or activate credentials.
